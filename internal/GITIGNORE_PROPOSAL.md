# Proposed `.gitignore` additions

This document originally proposed (without applying) a set of `.gitignore` additions. **Status update from the `chore/remove-gitbook-secrets` task:** that follow-up task was explicitly instructed to add `.mcp.json`, `.reticle.json`, `.env`, `.env.*`, `!.env.example` to `.gitignore`, and did so (plus kept the pre-existing `.claude`/`.codex` rules). Those four lines below are therefore **now applied**, not just proposed. `internal/`, `AUDIT_REPORT.md`, `next-env.d.ts`, `*.tsbuildinfo`, and `*.tgz` remain **proposed only** — they're unrelated to GitBook and were correctly left alone by that task's "don't touch anything unrelated to GitBook" scope limit. The current `.gitignore` already ignores `.claude` and `.codex` (added in a prior session) but, as noted in `internal/FILE_CLASSIFICATION.md`, that doesn't untrack the files already committed under those directories.

**Applied** (by `chore/remove-gitbook-secrets`):

```gitignore
# AI tool / integration configs that may carry credentials
.mcp.json
.reticle.json

# Environment files — never commit real secrets, example files are fine
.env
.env.*
!.env.example
```

- `.mcp.json` — was tracked and contained a live API token (see `internal/FILE_CLASSIFICATION.md`); now untracked via `git rm --cached` and stripped of its contents. This gitignore line only stops *future* re-additions; it does not remove the old token from history.
- `.reticle.json` — workspace/project-linkage metadata with no value to consumers of the open-source repo. Still tracked (left alone — untracking it was out of this task's GitBook-only scope); only the `.gitignore` line was added as explicitly instructed.
- `.env`, `.env.*`, `!.env.example` — no `.env` file exists in the repo yet, so this is precautionary. The `!.env.example` negation means a future `.env.example` template file can still be committed on purpose.

**Still proposed, not applied** (unrelated to GitBook, left for a separate hygiene task — see `internal/PROGRESS.md` P2-2):

```gitignore
# Internal-only docs — never publish
internal/
AUDIT_REPORT.md

# Generated by Next.js / TypeScript — never commit
next-env.d.ts
*.tsbuildinfo

# Stale/accidental build artifacts
*.tgz
```

Notes on each:
- `internal/` — working material for agents/maintainers, not for the public repo.
- `AUDIT_REPORT.md` — contains exact vulnerable file:line details for an unpatched security issue; per the audit task's hard rules such detail must not be public. It's currently untracked, so adding this line keeps it that way.
- `next-env.d.ts`, `*.tsbuildinfo` — tool-generated, regenerated automatically by `next dev`/`next build`/`tsc`, and are currently tracked only because nothing ever ignored them.
- `*.tgz` — catches the stale `packages/create-orycms/create-orycms-0.1.0.tgz` and prevents any future accidental tarball commit from any package.

Applying these additions does not remove anything from git history. Files already tracked need the explicit `git rm --cached` commands proposed in `internal/FILE_CLASSIFICATION.md` in addition to this `.gitignore` change.
